# 外贸经理个人工作台 产品需求文档（PRD）V1.5

> **一句话定位**：把分散的客户信息和跟进任务放回 WhatsApp / Telegram 工作现场，减少查找、记录和记忆成本。
>
> **产品形态**：本地工作台（浏览器加载）+ Chrome 插件 + 本地后台服务。
>
> **版本原则**：V1 只解决"客户信息一处治理 + 跟进提醒闭环"，业务数据仅存本机，不做 AI、自动发消息和多人协作。

### 1.1 本次修订（V1.5）

V1.5 回流与架构 V1.3 对齐时发现的 5 处隐含假设修正。V1.4 写于"数据存浏览器 IndexedDB"的认知下，V1.3 架构已确认业务数据由本地后台服务管理，浏览器仅作为工作台 UI 加载入口。本次修正不改变产品功能，只让数据存储、安装启动、通知渠道的隐含假设与新架构一致：

1. **数据存储位置**：业务数据由本地后台服务在本机文件管理，与浏览器数据、插件配置相互独立。清除浏览器数据、删除浏览器配置或卸载插件**不会**删除业务数据（§3.2、§8.3、§10.2 修正）
2. **安装与启动**：用户先安装本地后台服务（安装包自动打开浏览器到工作台），再从浏览器商店单独安装插件并完成配对（§3.3 修正）
3. **提醒触达渠道**：到期通知由本地后台服务直接调用系统通知发出，不依赖浏览器是否打开（§6.4 修正）
4. **关闭工作台标签**：关闭浏览器标签后本地后台服务继续运行，提醒照常触达；只有从托盘"彻底退出"才会停止后台（§6.4、§9.1 修正）
5. **数据丢失场景**：只有磁盘损坏、误删后台服务数据目录或"清空全部数据"操作会导致业务数据丢失；浏览器层操作不再列入数据丢失风险（§8.3、§10.2 修正）

> V1.4 历史修订见版本归档。

### 1.1 本次修订（V1.4）

V1.4 回流 2026-07-28 需求反述确认的 5 项产品决策：

1. **状态流转方式**：所有状态变更均由用户手动触发或时间到期触发，系统不根据消息内容自动流转状态（影响 §6.4 / §6.7 / §6.8）
2. **"等待客户回复"提醒类型**：保留该类型，但系统不监听新消息；用户手动确认"已收到回复"后状态从"等待中"流转为"待处理"。连带删除 G0 §4.1"新消息识别"技术验证项、§4.2 合规边界"新消息状态"读取项，G0 合规面简化
3. **"当期"周期定义**：滚动 30 天（影响 §2.3 北极星指标口径）
4. **客户分级与项目分级的关系**：按待办关联对象分流，非按客户阶段切换。客户分级 A/B/C 挂在客户上，用于该客户名下未关联项目的待办排序；项目分级 S/A/B/C 挂在项目上，用于该项目关联的待办排序。一个客户可有多个项目，同一客户名下不同待办可能分别走项目分级或客户分级（影响 §6.5 / §6.6 / §6.7）
5. **本地优先**：客户、联系人、跟进、提醒和项目数据只保存在用户本机，不建设云端业务数据存储，不做账号、登录和自动同步（影响 §3 / §7 / §8 / §9）

## 2. 背景与目标

### 2.1 核心问题

1. 客户散落在 Excel、邮件和社媒账号中，查找上下文慢
2. 跟进节奏依赖记忆，容易错过机会
3. 客户和项目缺少统一优先级，精力分配失焦
4. 跟进结果没有形成可复盘的数据

### 2.2 V1 产品目标

上线 90 天内，让试点用户能够在 WhatsApp / Telegram 对话现场完成“识别客户、查看档案、记录跟进、设置提醒”，并使到期跟进按时完成率达到 90%。

### 2.3 指标

| 类型 | 指标 | 口径 | 目标 |
|------|------|------|------|
| 北极星指标 | 到期跟进按时完成率 | 到期后 24 小时内完成的提醒数 / 滚动 30 天内到期提醒总数；该滚动窗口内至少 20 条提醒 | 30 天达到 90% |
| 核心过程指标 | 客户自动匹配正确率 | 自动匹配正确的会话数 / 自动匹配会话总数 | >= 95% |
| 核心过程指标 | 提醒处理率 | 已完成、稍后处理或明确忽略的提醒数 / 已触达提醒总数 | >= 90% |
| 结果指标 | MTR | 试点前后各连续 5 个工作日，由用户按相同口径记录机械性事务耗时 / 总工作时长 | 90 天由 81% 降至 <= 55% |

> MTR 是阶段性调研指标，不由产品埋点直接计算，也不作为单次版本发布门槛。

所有产品使用指标均在本机计算和展示，不自动上报。试点验证需要汇总数据时，由用户主动导出不含客户身份和消息正文的统计报告。

### 2.4 不做什么

- 不做 AI 画像、AI 话术、AI 摘要和 AI 行动建议
- 不做自动收发消息
- 不做多人协作和复杂权限
- 不做 ERP、财务系统和移动 App
- 不做微信、邮件提醒
- 不做 LinkedIn、Facebook 等其他平台
- 不做云端业务数据存储、账号登录和跨设备自动同步
- 不为 V2 预装向量数据库或增加未使用的 AI 字段

## 3. 产品形态与核心流程

### 3.1 双端职责

| 端 | 使用场景 | V1 职责 |
|----|---------|---------|
| Chrome 插件 | 用户正在 WhatsApp Web / Telegram Web 对话 | 识别客户、查看档案、标记消息、设置和处理提醒 |
| 本地工作台 | 用户集中整理客户和项目 | 导入客户、维护档案、管理项目、查看全部待办 |

插件与本地工作台共用同一份本机数据。业务数据不上传到产品服务器，不做云同步。

### 3.2 首次使用与本地工作区

- 用户首次安装本地后台服务后，安装程序自动打开浏览器进入本地工作区，无需注册、登录、邮箱或设备凭证
- 插件浮窗、popup 和本地工作台使用同一份本机业务数据，该数据由本地后台服务管理，与浏览器数据、插件配置相互独立
- V1 不支持跨设备自动同步；更换设备时通过用户主动导出的受密码保护备份文件迁移
- 首次导入客户后提示用户创建备份；距离上次备份超过 7 天时在工作台显示非阻断提醒
- 清除浏览器数据、删除浏览器配置或卸载插件不会删除业务数据，但会导致插件需要重新配对；执行卸载插件时仍提示重新配对成本

### 3.3 核心流程

1. 用户安装本地后台服务，安装程序自动打开浏览器进入本地工作区
2. 用户在工作台按引导从浏览器商店安装插件并完成与本机后台服务的配对
3. 用户在本地工作台导入客户并补充社媒账号
4. 用户打开 WhatsApp / Telegram 一对一对话
5. 插件识别社媒账号并匹配客户档案
6. 用户查看历史、标记关键消息或手动补充跟进记录
7. 用户设置下次跟进日期，或标记为"等待客户回复"状态
8. 到期后，系统通过系统通知、插件角标和待办列表提醒
9. 用户完成、稍后处理或忽略提醒，或手动确认"已收到回复"结束等待状态，系统记录结果

## 4. 上线前门禁：平台可行性验证

WhatsApp Web 和 Telegram Web 是 V1 核心依赖。正式承诺研发排期前，必须分别完成技术与合规验证。

### 4.1 技术验证项

每个平台至少使用 30 个一对一会话样本验证：

- 能稳定识别当前会话，或提供可靠的人工绑定替代流程
- 能展示独立浮窗，不遮挡原生输入框、消息区和导航
- 用户点击"标记"后，能读取其主动选择的单条消息并保存
- 能从插件待办跳回正确会话；不能深链时，至少打开平台并给出可搜索账号
- 页面刷新、切换会话和列表懒加载后仍可恢复工作

### 4.2 合规边界

- 不自动发送、修改或删除平台消息
- 不批量抓取历史对话
- 仅在用户主动标记消息时读取该条消息正文
- 默认只读取当前会话的身份标识
- 权限用途、保存内容和删除方式在安装及首次使用时明确告知用户
- 法务或平台政策评估未通过的能力不得进入 V1

### 4.3 门禁结论

V1 必须同时正式支持 WhatsApp Web 和 Telegram Web。两个平台均通过技术验证和合规评估后，G0 才算完成；任一平台未通过时不得将 V1 标记为正式上线，需重新进行产品范围评审。

## 5. 核心数据规则

### 5.1 最小数据关系

| 对象 | 关键关系 |
|------|---------|
| 客户 | 可有多个联系人、社媒账号、项目、跟进记录和提醒 |
| 联系人 | 归属一个客户，可关联多个社媒账号 |
| 社媒账号 | 由“平台 + 平台账号标识”唯一确定 |
| 项目 | 归属一个客户，包含阶段、分级、风险和里程碑 |
| 跟进记录 | 归属客户，可选关联项目和原始社媒消息 |
| 提醒 | 归属客户，可选关联项目，具有到期、完成、稍后和忽略状态 |

### 5.2 身份匹配

匹配优先级：

1. 已人工绑定的“平台 + 平台账号标识”
2. 标准化后的手机号精确匹配
3. 平台用户名精确匹配

匹配到多个客户时不得自动选择，必须展示候选客户供用户确认。无法取得稳定标识时，允许用户把当前会话人工绑定到客户；用户可解绑或改绑。

### 5.3 导入去重

- 邮箱忽略大小写后精确命中、E.164 格式手机号命中，或平台账号命中时，判定为重复候选
- 公司名只用于提示候选，不得仅凭公司名自动覆盖
- 用户可逐条或批量选择“合并、跳过、保留为新客户”
- 合并前展示字段冲突；系统不得静默覆盖非空字段
- 导入结果必须提供成功、失败、重复和跳过数量，以及失败原因下载

## 6. V1 功能需求

### 6.1 客户导入与档案管理（本地工作台）

用户可上传 `.xlsx` / `.csv`，完成字段映射、预览、校验和导入。客户列表支持搜索、筛选、排序、新建、编辑、合并、软删除和 30 天内恢复。

客户档案至少包含：公司、联系人、国家/地区、来源、客户分级、社媒账号、跟进时间线、关联项目和未完成提醒。

**验收要点**：

- 合法模板 1000 行可完成预览和导入
- 错误行不影响合法行导入，并能查看具体错误原因
- 重复候选按 5.3 规则处理
- 删除后插件端不可继续匹配；恢复后重新可用

### 6.2 客户识别与档案浮窗（插件）

进入一对一会话后，插件按 5.2 规则识别客户。

- 唯一命中：显示基础信息、分级、最近一条跟进记录、完整时间线入口和未完成提醒
- 多个候选：要求用户选择并确认绑定
- 未命中：提供新建客户或绑定已有客户入口
- 群组、频道或无法识别场景：明确显示“不支持自动识别”，不得静默消失

浮窗只使用独立容器或覆盖层，不改写宿主页已有消息内容；支持折叠和恢复。

### 6.3 跟进记录（插件 + 本地工作台）

用户可通过两种方式新增记录：

1. 主动标记当前会话中的单条消息
2. 手动填写跟进记录

记录字段包括时间、类型、备注、消息正文、客户和可选项目。只有用户点击标记后才读取该条消息正文。

保存失败时必须保留当前编辑内容并允许重试，重复提交不得产生重复记录。用户可编辑和删除自己创建的记录。

### 6.4 跟进提醒（插件 + 本地工作台）

提醒类型：

- 固定时间：3 天后、1 周后、自定义日期和时间
- 等待客户回复：用户手动确认"已收到回复"后，状态从"等待中"流转为"待处理"；系统不自动监听新消息，不自动改变状态
- 暂不跟进：必须选择原因，可选填写重新评估日期

到期触达渠道：

- 操作系统级通知（由本地后台服务直接发出，无需浏览器打开）
- 插件图标角标
- 插件 popup 待办列表
- 本地工作台待办列表

V1 不包含微信和邮件推送。本地后台服务运行时（无论浏览器是否打开），到期提醒必须准时触达；后台服务未运行期间错过的提醒，应在下次启动后补发并标记为逾期。

**状态流转总原则**：提醒状态变更（到期、完成、稍后处理、忽略、已收到回复）均由用户手动触发或时间到期触发，系统不根据消息内容自动流转状态。

用户可以完成、稍后处理或忽略提醒。连续逾期 3 天的提醒由系统自动提升优先级（仅影响排序权重，不改变提醒状态），同一提醒每天最多主动通知一次。

### 6.5 插件 popup

popup 展示前 5 条待办，并提供"查看全部"。排序规则依次为：

1. 已逾期
2. 高风险项目
3. 分级：关联项目的待办按项目分级 S、A、B、C 排序；未关联项目的待办按客户分级 A、B、C 排序
4. 到期时间从早到晚

> 分级按待办关联对象分流：一个客户可有多个项目，同一客户名下不同待办可能分别走项目分级或客户分级。

点击客户后优先打开对应会话；无法深链时打开平台并复制可搜索账号。

### 6.6 客户分级

客户分为 A、B、C 三级，由用户手动设置。客户分级用于该客户名下**未关联项目**的待办排序；系统不自动推断或修改分级。客户即使有项目，客户分级仍保留，用于该客户名下未关联项目的待办。

### 6.7 项目管理

用户可新建、编辑、归档和关闭项目。项目字段包括：

- 项目名称、关联客户、币种、金额
- 成交概率、预计成交日期
- 阶段：需求确认、方案/样品、报价、谈判、成交、失单
- 分级：S、A、B、C，由用户手动设置
- 失单原因或关闭原因

项目分级 S、A、B、C 用于**该项目关联**的待办排序。项目阶段（需求确认、方案/样品、报价、谈判、成交、失单）由用户手动切换，系统不自动推进阶段。金额乘成交概率仅作为参考值展示，不用于不同币种项目之间的自动排序。

### 6.8 项目风险与里程碑

项目可添加风险和里程碑：

- 风险包含说明、严重度、状态和处理日期；风险状态由用户手动维护
- 里程碑包含名称、日期和完成状态；完成状态由用户手动标记
- 高风险项目进入 popup 待办排序
- 未完成里程碑在到期前 3 天由系统自动生成提醒（属于提醒生成，非状态流转）
- 风险连续 7 天未处理的，由系统自动提升优先级（仅影响排序权重，不改变风险状态）

## 7. 异常与状态规则

| 场景 | 处理方式 |
|------|---------|
| 数据读取失败 | 显示可理解的错误和重试入口，不使用空数据覆盖现有数据 |
| 本机存储空间不足 | 保留当前未提交内容，提示释放空间或备份后重试 |
| 同一会话匹配多个客户 | 停止自动匹配，要求人工确认 |
| 保存中断 | 保留用户输入；重新提交不得产生重复记录 |
| 提醒重复触发 | 同一提醒同一状态只保留一条通知 |
| 客户被合并 | 跟进、项目、提醒和社媒绑定迁移到保留客户 |
| 客户被删除 | 取消未完成提醒并解除插件匹配；恢复时一并恢复 |
| 平台 DOM 发生变化 | 关闭受影响的读取能力并显示降级提示，不影响本地工作台数据 |

## 8. 非功能与数据安全

### 8.1 性能和兼容

- 测试基线：Chrome 最新两个版本、普通办公电脑、1000 个客户档案和 10000 条跟进记录
- 客户浮窗 P95 展示时间 <= 1 秒
- 1000 行合法模板的导入处理时间 P95 <= 30 秒
- 支持 Edge 最新两个版本；最低分辨率 1366 x 768
- 除 WhatsApp / Telegram 页面本身外，客户档案、任务、项目和导入功能在断网时仍可使用

### 8.2 本地存储与隐私

- 插件仅申请实现当前功能所需的域名、存储和通知权限
- 客户、联系人、社媒绑定、跟进、提醒、项目和设置由本地后台服务保存在用户本机文件，与浏览器数据、插件配置相互独立
- 首次使用无需注册或登录，产品不采集用户邮箱、手机号等账号信息
- 业务数据、消息正文和使用行为不上传到产品服务器，不接入远程埋点或云端日志
- 产品必须说明本地数据的保存位置、占用空间、备份方式和删除方式
- 本地数据安全依赖用户设备和操作系统账号；产品不得宣称能防御已经取得本机权限的攻击者

### 8.3 备份、恢复和删除

- 用户可将客户、联系人、项目、跟进和提醒导出为 Excel；Excel 为明文文件，导出前必须提示妥善保管
- 用户可导出包含全部业务数据的受密码保护备份文件
- 恢复前必须校验备份完整性和兼容性；恢复失败不得覆盖当前数据
- 单条客户软删除后进入本地回收站，30 天内可恢复，之后自动永久删除
- “清空全部数据”必须二次确认，成功后立即删除本地数据库且不可撤销；用户自行保存的备份文件不受影响
- 插件卸载、浏览器配置删除不会删除业务数据，只需重新安装插件并配对；磁盘损坏或误删后台服务数据目录造成的数据丢失只能通过用户持有的备份文件恢复

## 9. 验收标准

### 9.1 V1 上线验收

- [ ] WhatsApp Web 和 Telegram Web 均通过第 4 章技术与合规门禁
- [ ] 首次安装无需注册或登录即可使用插件和本地工作台
- [ ] 插件浮窗、popup 和本地工作台展示的数据保持一致
- [ ] 导入、建档、识别、标记、设置提醒、收到通知、处理提醒的主流程可完整跑通
- [ ] 身份多候选、保存失败、重复导入、权限拒绝和存储空间不足场景有明确处理
- [ ] 产品后台服务运行时（无论浏览器是否打开），到期提醒在 5 分钟内触达；重新启动后能补发已错过提醒
- [ ] 保存中断后不会产生重复数据或以空数据覆盖原数据
- [ ] 产品升级后客户、跟进、项目、关联关系和提醒状态保持完整；升级失败不得破坏原数据
- [ ] 加密备份可在全新本地数据库中完整恢复，密码错误或文件损坏时不得覆盖当前数据
- [ ] 网络检查确认业务数据、消息正文和使用行为未发送到产品服务器
- [ ] 第 8 章性能、安全和删除要求通过测试
- [ ] 无阻断主流程或造成数据丢失的已知严重缺陷

### 9.2 上线后验证

试点用户不少于 5 人，且每人当期产生至少 20 条到期提醒。

- 上线 30 天：到期跟进按时完成率 >= 90%
- 上线 30 天：客户自动匹配正确率 >= 95%
- 上线 30 天：提醒处理率 >= 90%
- 上线 90 天：按统一日记法测得 MTR <= 55%

## 10. 里程碑与风险

### 10.1 里程碑

| 阶段 | 交付物 | 退出条件 |
|------|--------|---------|
| G0 可行性验证 | 两个平台技术 Spike + 合规结论 | WhatsApp 和 Telegram 均通过，明确各自降级方案 |
| V1.0 MVP | 第 6 章全部功能 | 第 9.1 节全部通过 |
| V1.5 | 转化漏斗、客户状态规则 | V1.0 连续使用 30 天且数据口径稳定 |
| V2.0 | AI 能力 | 根据 V1 实际使用数据另立 PRD |

### 10.2 主要风险

| 风险 | 应对 |
|------|------|
| 平台页面变化导致插件失效 | 独立适配层、版本回归测试和降级提示；本地工作台保持可用 |
| 平台政策不允许读取 | 以合规门禁为准，必要时只保留人工绑定和手动记录 |
| 自动匹配误关联客户 | 只允许稳定标识自动匹配；多候选必须人工确认 |
| 产品后台服务未运行导致提醒延迟 | 待办列表保留逾期任务，下次启动时补发通知 |
| 用户录入成本过高 | 导入预览、批量冲突处理和会话内快捷建档 |
| 产品升级导致本地数据不兼容 | 升级前自动备份；升级失败时保留原数据并允许恢复 |
| 卸载插件、清理浏览器数据需要重新配对 | 安装包提供配对引导；重新安装插件即可恢复 |
| 磁盘故障或误删后台服务数据目录导致数据丢失 | 首次导入后提示备份，超过 7 天未备份时持续显示非阻断提醒 |
| 本机账号被入侵导致数据泄露 | 明确本地安全边界，依赖操作系统账号保护，加密备份不得保存明文密码 |
