# DealPilot PRD V2.0 G0 决策补充

> 状态：已确认，可进入 Atomic CRM 本地基线验证
> 日期：2026-07-30
> 决策范围：个人云账号、数据存储、隐私与发布前置条件
> 关联计划：`docs/cloud-multiplatform-refactor-plan.md`

## 1. 文档关系

本文件是 V2 产品目标的 G0 决策补充。V1 PRD 和系统架构文档继续作为本地单机版本的历史基线；本文件在账号体系、云端存储、跨设备访问、数据保留和隐私承诺方面取代 V1 的相反约束。

V2 不再承诺“业务数据永不上传”。现有 V1 用户默认继续使用本地模式，只有在看到云端存储说明并明确同意后，才可创建账号和迁移数据。拒绝或放弃迁移不会修改或删除本地 SQLite 数据。

## 2. 产品范围

DealPilot V2 首版是个人云 CRM：

- 每个自然人账号拥有一套独立业务数据。
- 同一账号可从 Web、PWA、移动端、浏览器扩展和已配对 Agent 访问同一份数据。
- 首版不支持 workspace、团队成员、角色、邀请、共享客户或企业 SSO。
- 公共云中的不同账号必须通过 PostgreSQL RLS 和数据库约束严格隔离。
- 后续若验证出团队协作需求，再单独设计从个人账户到 workspace 的迁移，不提前建设。

## 3. G0 决策

| 项目 | 决策 |
|---|---|
| 开源基线 | 采用 Atomic CRM 的固定 commit 作为 V2 Web/PWA 和 Supabase/PostgreSQL 基线，保留 MIT 许可证和来源记录 |
| 开发部署 | 第一阶段仅在开发者本机运行；Atomic CRM、Supabase/PostgreSQL、Auth、Storage 和 Edge Functions 使用本地开发栈，不开放公网入口 |
| 开发数据 | 只允许合成数据或完成不可逆匿名化的数据，不得把真实客户资料导入本地调试环境 |
| 生产区域 | Cloud Beta 首选新加坡区域；进入真实用户试点前完成跨境数据和供应商评审 |
| 身份服务 | 首版使用 Supabase Auth 管理邮箱注册、验证、登录、密码重置和会话；不自行存储密码，不部署 Keycloak |
| 账号隔离 | 所有云端业务记录绑定 `owner_user_id`；RLS 使用 `auth.uid()` 授权；客户端不得获得 `service_role` |
| 事实源 | 用户确认迁移后，PostgreSQL 永久成为业务数据唯一事实源；不建设 PostgreSQL 到 SQLite 的反向同步 |
| 发布模式 | 先本地开发，再测试环境和受控 Cloud Beta；未通过生产发布门时不得处理真实用户数据 |

## 4. 数据分类与保留

| 数据类别 | 默认保留规则 |
|---|---|
| 活跃账号业务数据 | 保留至用户删除记录或关闭账号 |
| 客户等业务实体的软删除记录 | 30 天内可恢复，期满后从主库永久删除 |
| 账号关闭 | 请求后立即停用访问，提供 30 天撤销期；撤销期结束后 7 天内清除主库和对象存储数据 |
| 云端备份 | 滚动保留 35 天；主库删除后最多再存在一个备份周期，到期自动淘汰 |
| 审计与安全日志 | 默认保留 180 天；禁止记录访问令牌、密码、消息正文和完整客户敏感字段 |
| 导入原文件和迁移临时分片 | 成功或失败结束后最多保留 7 天，随后自动删除 |
| 本地迁移快照 | 用户确认迁移后至少只读保留 30 天；由用户在本机导出或删除，不属于云端备份 |

依法需要保全的数据可以延长保留，但必须记录原因、范围、责任人和到期时间，并在隐私政策中披露适用情形。

## 5. 隐私与安全承诺

- 首次启用 Cloud Beta 前，界面必须说明存储区域、处理的数据类别、用途、保留周期、删除方式和主要子处理方，并取得可追溯的明确同意。
- 对中国大陆用户将数据存储到新加坡属于跨境处理；真实用户试点前必须完成适用的个人信息保护评估、单独同意和合同/备案要求判断。
- 所有公网传输使用 TLS；数据库、对象存储和备份启用静态加密；生产密钥进入云密钥管理服务。
- 应用日志默认最小化并脱敏，不采集消息正文、访问令牌、密码或无关客户字段。
- 用户可以导出自己的全部数据并关闭账号；删除任务必须可审计、可重试并有完成状态。
- 浏览器、PWA、移动端和扩展只能获得 Supabase anon key 与当前用户会话，禁止包含 `service_role`。
- Atomic CRM 默认允许所有认证用户访问业务数据的 RLS 策略不得进入测试或生产环境。

## 6. 生产发布门

进入包含真实数据的测试环境或 Cloud Beta 前，必须同时满足：

1. 隐私政策、服务条款、云端存储同意文案和账号删除流程通过产品确认。
2. 新加坡区域、Supabase/云供应商、邮件供应商和全部子处理方完成记录。
3. 针对目标用户所在地完成跨境、数据主体权利和安全事件通知要求评审。
4. 两个真实测试账号的 RLS、复合外键、Storage 和 RPC 隔离矩阵全部通过。
5. 备份恢复、账号删除、日志脱敏、密钥轮换和依赖漏洞扫描完成演练。
6. 试点账号默认关闭，由功能开关逐个启用。

以上生产发布门不阻塞本地开发和合成数据测试，但任何一项未完成时都不得导入或处理真实客户数据。

## 7. G0 验收结论

- 产品方向从“本地单用户”变更为“个人账号 + 跨设备 + 云端单一事实源”。
- 首版明确不建设团队 workspace 或角色系统，但保留严格的账号间数据隔离。
- Atomic CRM/Supabase 取代 NestJS/Keycloak，减少重复建设 CRM UI、认证和普通 CRUD。
- V1 用户不会被静默迁移，云端存储必须显式选择。
- 工程可进入 Atomic CRM 本地基线验证；生产真实数据仍受第 6 节发布门约束。
